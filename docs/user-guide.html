คู่มือผู้ใช้งาน · ฉบับภาษาไทย

ใช้งาน Marketplace ได้ครบทุกบทบาท แบบทีละขั้นตอน

คู่มือนี้ยึดหน้าจอและการทำงานที่มีอยู่จริงในระบบ ณ วันที่ 19 สิงหาคม 2026 ครอบคลุมผู้ซื้อ ผู้ขาย และผู้ดูแลระบบ พร้อมแยกส่วนทดสอบและงานที่ยังต้องดำเนินการด้วยคนอย่างชัดเจน

ภาษาเริ่มต้น ไทย เส้นทางตัวอย่าง /th/... ไม่มีภาพหน้าจอ
ใช้งานจริง Mock / โหมดทดสอบ ดำเนินการด้วยคน ข้อจำกัดปัจจุบัน
ผู้ซื้อ ค้นหา ซื้อ ชำระเงิน ติดตาม รีวิว และคืนสินค้า ผู้ขาย สมัครร้าน จัดการสินค้า สต็อก ออเดอร์ และการเงิน ผู้ดูแลระบบ อนุมัติ ตรวจสอบ ดูแลเนื้อหา และติดตามความเสี่ยง

บัญชี ภาษา และการเข้าสู่ระบบ

พื้นฐานร่วมก่อนเริ่มใช้งานแต่ละบทบาท

หนึ่งบัญชีเป็นได้ทั้งผู้ซื้อและผู้ขาย

ระบบมี role ระดับแพลตฟอร์มเพียง USER และ ADMIN เท่านั้น ผู้ขายคือผู้ใช้ทั่วไปที่สมัครร้านและมีร้านสถานะ ACTIVE จึงยังใช้ฟังก์ชันผู้ซื้อด้วยบัญชีเดิมได้

A1สมัครบัญชีใหม่และยืนยันอีเมล

เส้นทาง: /th/signup → /th/verify-email

  1. เปิดหน้า สมัครสมาชิก แล้วกรอกชื่อ อีเมล และรหัสผ่านอย่างน้อย 8 ตัวอักษร
  2. กดปุ่มสมัคร ระบบจะสร้างบัญชีและพาไปขั้นตอนยืนยันอีเมล
  3. ตรวจอีเมลเพื่อรับ OTP แล้วกรอกรหัสในหน้า ยืนยันอีเมล
  4. เมื่อยืนยันสำเร็จ ให้เข้าสู่ระบบด้วยอีเมลและรหัสผ่านเดิม
สภาพแวดล้อม Local

ค่าเริ่มต้นส่งอีเมลเข้า server log ไม่ได้ส่งไปยังกล่องจดหมายจริง ผู้ดูแลระบบทดสอบต้องนำ OTP จาก log มาให้ผู้ใช้

A2เข้าสู่ระบบ ออกจากระบบ และกู้รหัสผ่าน

เส้นทาง: /th/login, /th/forgot-password, /th/reset-password

  1. เปิดหน้า เข้าสู่ระบบ กรอกอีเมลและรหัสผ่าน แล้วกดเข้าสู่ระบบ
  2. หากเปิดหน้าที่ต้องล็อกอินมาก่อน ระบบจะพากลับไปหน้าดังกล่าวหลังเข้าสู่ระบบสำเร็จ
  3. หากลืมรหัสผ่าน เลือก ลืมรหัสผ่าน กรอกอีเมล รับ OTP และตั้งรหัสผ่านใหม่
  4. เมื่อต้องการออกจากระบบ ใช้เมนูบัญชีบนแถบด้านบนหรือเมนูด้านข้าง แล้วเลือก ออกจากระบบ
A3เลือกภาษาและเข้าใจรูปแบบ URL
  1. ใช้ตัวเลือกภาษาบนส่วนหัวของเว็บไซต์เพื่อสลับระหว่างไทยและอังกฤษ
  2. หน้าไทยขึ้นต้นด้วย /th เช่น /th/orders
  3. หน้าอังกฤษขึ้นต้นด้วย /en เช่น /en/orders
  4. คู่มือนี้ใช้เส้นทางภาษาไทยทั้งหมด หากระบบอยู่ภาษาอังกฤษให้เปลี่ยน /th เป็น /en

Buyer guide

คู่มือผู้ซื้อ

ตั้งแต่ค้นหาสินค้าจนถึงรีวิวหรือขอคืนสินค้า

ใช้งานจริง
ค้นหาสินค้า→ เลือกตัวเลือก→ รถเข็น→ Checkout→ ชำระเงิน→ ติดตามออเดอร์
B1ค้นหา กรอง และเปิดดูสินค้า

เส้นทาง: /th, /th/search, /th/categories/{categoryId}, /th/deals

  1. เริ่มจากหน้าแรก เลือกหมวดหมู่ ดีล หรือแตะช่องค้นหาด้านบน
  2. พิมพ์คำค้นแล้วกดค้นหา ระบบจะแสดงสินค้าและบันทึกคำค้นล่าสุดไว้ในอุปกรณ์
  3. ใช้ ตัวกรองและเรียงลำดับ เพื่อเลือกหมวดหมู่ แบรนด์ ช่วงราคา คะแนน สินค้ามีสต็อก ส่งฟรี หรือสินค้าลดราคา
  4. เลือกการเรียงตามความเกี่ยวข้อง ราคา ยอดขาย หรือคะแนน แล้วแตะการ์ดสินค้าเพื่อเปิดรายละเอียด
  5. ในหน้าร้านค้า สามารถดูข้อมูลร้าน สินค้าทั้งหมด และกดติดตามร้านได้
B2เลือกตัวเลือกสินค้า เพิ่มรถเข็น และซื้อทันที

เส้นทาง: /th/products/{productId}

  1. ตรวจชื่อ ราคา คะแนน รีวิว รายละเอียดร้าน และจำนวนคงเหลือ
  2. หากสินค้ามีสี ขนาด หรือตัวเลือกอื่น ให้เลือกให้ครบจนระบบระบุ variant ที่ต้องการ
  3. ปรับจำนวนโดยไม่เกินสต็อกที่แสดง
  4. กดรูปหัวใจเพื่อเพิ่ม Wishlist, กด ติดตามร้าน หรือ แชตกับผู้ขาย ได้เมื่อล็อกอินแล้ว
  5. กด เพิ่มลงรถเข็น เพื่อซื้อภายหลัง หรือกด ซื้อทันที เพื่อเพิ่มสินค้าแล้วไปหน้ารถเข็น
  6. หากต้องการถามรายละเอียด ใช้ส่วนคำถามสินค้า พิมพ์คำถามแล้วกดส่ง ผู้ขายจะตอบจากหน้าจัดการสินค้า
ซื้อทันทีในระบบปัจจุบัน

ปุ่มนี้เพิ่มสินค้าลงรถเข็นและเปิดหน้ารถเข็น ยังไม่ข้ามไป Checkout โดยตรง

B3จัดการรถเข็นและเลือกสินค้าที่จะชำระ

เส้นทาง: /th/cart

  1. เปิดเมนู รถเข็น สินค้าจะถูกจัดกลุ่มตามร้านค้า
  2. เลือก checkbox เฉพาะรายการที่ต้องการซื้อ หรือเลือกทั้งร้าน
  3. ใช้ปุ่ม − / + เพื่อแก้จำนวน หรือปุ่มถังขยะเพื่อลบรายการ
  4. ตรวจยอดรวมของรายการที่เลือก หากยังไม่เลือกรายการ ปุ่ม Checkout จะถูกปิด
  5. กด Checkout เพื่อไปหน้าตรวจสอบคำสั่งซื้อ
B4เพิ่มที่อยู่และทำ Checkout

เส้นทาง: /th/account/addresses → /th/checkout?items=...

  1. หากยังไม่มีที่อยู่ ให้เปิด โปรไฟล์ → ที่อยู่ กรอกผู้รับ เบอร์โทร ที่อยู่ เมือง จังหวัด รหัสไปรษณีย์ และประเทศ แล้วบันทึก
  2. ตั้งที่อยู่ที่ใช้บ่อยเป็น ค่าเริ่มต้น หรือเลือกที่อยู่อื่นบนหน้า Checkout
  3. ตรวจรายการแยกตามร้าน วิธีส่งมาตรฐาน และยอดสรุปที่ระบบคำนวณจากข้อมูลฝั่งเซิร์ฟเวอร์
  4. หากมีคูปอง ให้กรอกรหัสแล้วกด ใช้คูปอง ตรวจข้อความว่าถูกใช้หรือถูกปฏิเสธเพราะเหตุใด
  5. เลือกช่องทางชำระเงิน จากนั้นกด สั่งซื้อ
  6. ระบบจะตรวจราคาและสต็อกอีกครั้ง สำรองสต็อก สร้างออเดอร์สถานะรอชำระ และแสดงลิงก์ไปหน้าชำระเงิน
ข้อจำกัด COD

หน้าจอมีตัวเลือกเก็บเงินปลายทาง แต่ backend ปัจจุบันยังสร้าง payment flow แบบเดียวกัน แนะนำให้ใช้ตัวเลือกบัตร/Payment Gateway จนกว่า COD จะเชื่อมครบ

B5ชำระเงินและตรวจผล

เส้นทาง: /th/payment/mock/{paymentId} หรือผู้ให้บริการภายนอก → /th/payment/return?orderId=...

  1. เปิดลิงก์ชำระเงินจากหน้า Checkout
  2. ใน Local/โหมดทดสอบ เลือก ชำระสำเร็จ หรือ ชำระไม่สำเร็จ บนหน้า Mock Payment
  3. ในระบบจริง ให้ดำเนินการบนหน้าผู้ให้บริการชำระเงิน แล้วกลับมายังหน้า Payment Return
  4. รอระบบตรวจ webhook หน้า Return อาจแสดง กำลังตรวจสอบ ชั่วคราว
  5. เมื่อสถานะเปลี่ยนเป็นสำเร็จ กด ดูคำสั่งซื้อ หากล้มเหลวให้ตรวจออเดอร์และลองดำเนินการตามข้อความที่ระบบแสดง
อย่าปิดความหมายของ Pending ว่า “จ่ายสำเร็จ”

การกลับจากหน้าชำระเงินไม่ใช่หลักฐานสำเร็จ ระบบเชื่อเฉพาะ webhook ที่ตรวจลายเซ็นแล้ว

B6ดูออเดอร์ ติดตามพัสดุ และแชตกับร้าน

เส้นทาง: /th/orders, /th/orders/{orderId}, /th/orders/{orderId}/tracking

  1. เปิดเมนู คำสั่งซื้อ แล้วกรองตามรอชำระ ชำระแล้ว จัดส่งแล้ว ส่งสำเร็จ หรือยกเลิก
  2. กด รายละเอียด เพื่อดูยอด สถานะชำระเงิน รายการสินค้า และ shipment แยกตามร้าน
  3. กด ติดตามคำสั่งซื้อ เพื่อดูบริษัทขนส่ง เลขพัสดุ และ timeline ของแต่ละ shipment
  4. กด แชตกับผู้ขาย บน shipment ที่ต้องการ ระบบจะเปิดห้องสนทนาที่ผูกกับออเดอร์นั้น
  5. ตรวจการแจ้งเตือนจากเมนูกระดิ่ง และกด อ่านทั้งหมด เมื่อต้องการล้างสถานะยังไม่อ่าน
B7รีวิวสินค้าที่ได้รับแล้ว

เส้นทาง: /th/orders/{orderId}/review

  1. เปิดรายละเอียดออเดอร์แล้วกด รีวิวสินค้า
  2. เลือกสินค้าที่มีสถานะส่งถึงแล้ว รายการที่ยังไม่ Delivered จะไม่แสดงเป็นตัวเลือก
  3. เลือกคะแนน 1–5 ดาวและกรอกความคิดเห็น
  4. กด ส่งรีวิว รีวิวจะเข้าสู่สถานะตรวจสอบก่อนเผยแพร่ตามกฎของระบบ
B8ขอคืนสินค้า/คืนเงิน

เส้นทาง: /th/orders/{orderId}/returns/new

  1. เปิดรายละเอียดออเดอร์แล้วกด คืนสินค้า/คืนเงิน
  2. เลือกสินค้าที่ส่งถึงแล้ว ระบบปัจจุบันสร้างคำขอครั้งละหนึ่งรายการ
  3. เลือกเหตุผล เช่น สินค้าเสียหาย สินค้าผิด ชิ้นส่วนไม่ครบ หรือปัญหาคุณภาพ
  4. กรอกรายละเอียด และหากมีหลักฐานให้ใส่ URL รูปภาพหนึ่งรายการต่อบรรทัด
  5. กด ส่งคำขอ แล้วรอผู้ขายหรือ Admin ตรวจสอบสถานะ
หลักฐานรูปภาพ

หน้าปัจจุบันรับ URL รูปภาพ ไม่ได้อัปโหลดไฟล์จากเครื่องโดยตรง

B9จัดการโปรไฟล์ ที่อยู่ Wishlist คูปอง และร้านที่ติดตาม

เส้นทาง: /th/profile, /th/wishlist, /th/vouchers, /th/followed-shops

  1. เปิด โปรไฟล์ เพื่อแก้ชื่อ ตรวจอีเมล เชื่อมและยืนยันเบอร์โทร หรือเปลี่ยนรหัสผ่าน
  2. เปิด Wishlist เพื่อดูสินค้าที่บันทึก เพิ่มลงรถเข็น หรือลบออก
  3. เปิด คูปอง เพื่อดูโค้ดที่ใช้ได้ แล้วกดใช้ในรถเข็น
  4. เปิด ร้านที่ติดตาม เพื่อดูสินค้าใหม่ของร้านและกลับเข้าหน้าร้าน
  5. เปิด แชต เพื่อดูห้องสนทนา อ่านข้อความ และส่งข้อความใหม่
B10สร้างลิงก์ Affiliate/Creator

เส้นทาง: /th/affiliates หรือ /th/creator

  1. เปิดเมนู Affiliate จากหน้าโปรไฟล์
  2. เลือกเป้าหมายของลิงก์ เช่น สินค้าหรือร้านค้า
  3. ใส่รหัสที่ต้องการ หรือปล่อยว่างให้ระบบสร้างรหัส
  4. กดสร้างลิงก์ แล้วใช้ปุ่ม คัดลอก เพื่อนำลิงก์ไปเผยแพร่
  5. ดูจำนวนคลิก conversion และ commission จากการ์ดสถิติ

สถานะที่ผู้ซื้อพบบ่อย

สถานะ ความหมาย สิ่งที่ควรทำ
PENDING_PAYMENT สร้างออเดอร์แล้วแต่ยังไม่ยืนยันการชำระ ไปหน้าชำระเงินและรอผล webhook
PAID ชำระเงินสำเร็จ รอร้านแพ็กสินค้า
PENDING_PACK / PACKED ร้านกำลังเตรียมสินค้า ติดตามจากรายละเอียดออเดอร์
SHIPPED ร้านกรอกบริษัทขนส่งและเลขพัสดุแล้ว เปิดหน้าติดตาม
DELIVERED ส่งถึงแล้ว รีวิวหรือขอคืนสินค้าหากมีปัญหา
REQUESTED ส่งคำขอคืนสินค้าแล้ว รอผู้ขาย/Admin พิจารณา

Seller guide

คู่มือผู้ขาย

สมัครร้าน ผ่านการอนุมัติ และจัดการงานขายประจำวัน

ต้องมีร้าน ACTIVE
สิทธิ์ Seller ไม่ได้มาจากการเปลี่ยน role

ต้องเข้าสู่ระบบด้วยบัญชี USER สมัครผู้ขาย และรอ Admin อนุมัติจนร้านเป็น ACTIVE เมนูปฏิบัติการของผู้ขายจึงจะใช้งานได้

สมัครผู้ขาย→ อัปโหลด KYC→ Admin อนุมัติ→ สร้างสินค้า→ ตรวจสต็อก→ แพ็กและส่ง
S1สมัครผู้ขายแบบ 4 ขั้นตอน

เส้นทาง: /th/seller/register/account

  1. สร้างบัญชีผู้ขาย: กรอกชื่อจริง/ชื่อนิติบุคคล อีเมล และเบอร์โทรติดต่อ
  2. ข้อมูลร้าน: กรอกชื่อร้าน slug และเลือกบุคคลธรรมดาหรือนิติบุคคล หากเป็นบริษัทต้องกรอกเลขทะเบียนและที่อยู่จดทะเบียน
  3. KYC: กรอกเลขประจำตัว/เลขภาษีและอัปโหลด PDF, JPG หรือ PNG ตามประเภทผู้ขาย บุคคลธรรมดาใช้เอกสารยืนยันตัวตนและยืนยันใบหน้า; บริษัทเพิ่มหนังสือรับรองบริษัท
  4. ยืนยันข้อมูล: ตรวจสรุป ยอมรับเงื่อนไข แล้วกด Submit for review
  5. ระบบพาไปหน้า สถานะคำขอผู้ขาย และล็อกการแก้ไขระหว่างสถานะ SUBMITTED
คำขอถูกปฏิเสธ

เปิด /th/seller/status อ่านเหตุผล กดแก้ไข อัปเดตข้อมูลหรือเอกสาร แล้วส่งคำขอใหม่

S2เลือกหน้าร้านและใช้ Dashboard

เส้นทาง: /th/seller

  1. หลังร้าน Active เปิดหน้า Seller Dashboard จากเมนูบัญชีผู้ซื้อหรือเข้าเส้นทาง Seller
  2. หากเป็นเจ้าของหลายร้าน ใช้ตัวเลือก ร้านที่ใช้งาน บน sidebar เพื่อสลับร้าน ข้อมูลทุกหน้าจะเปลี่ยนตามร้านที่เลือก
  3. ตรวจ KPI, งานจัดส่งค้าง, สินค้าใกล้หมด, รีวิวล่าสุด และข้อมูลภาพรวมร้าน
  4. ตั้ง Vacation mode หรือเปิด/ปิด Chat ได้จากส่วนตั้งค่าร้าน
  5. แก้คำอธิบายร้าน นโยบายการจัดส่ง และนโยบายคืนสินค้าทั้งภาษาไทย/อังกฤษ แล้วบันทึก
S3สร้างสินค้า ตัวเลือก รูปภาพ และเผยแพร่

เส้นทาง: /th/seller/products → /th/seller/products/new

  1. เปิดเมนู สินค้า แล้วกดสร้างสินค้าใหม่
  2. กรอกชื่อ slug คำอธิบาย หมวดหมู่ แบรนด์ สภาพสินค้า แหล่งผลิต highlights และสเปกที่หมวดหมู่กำหนด
  3. บันทึกเป็น DRAFT ก่อน จากนั้นอัปโหลดรูป/วิดีโอ จัดลำดับรูป และเลือกรูปหลัก
  4. เพิ่มชื่อตัวเลือกและค่าตัวเลือกได้สูงสุด 2 กลุ่ม เช่น สีและขนาด แล้วสร้างแถว variant จากชุดตัวเลือก
  5. กรอก SKU ราคา และสถานะของแต่ละ variant ตรวจว่าไม่มีชุดตัวเลือกซ้ำ
  6. ตรวจรายการ Readiness ให้ผ่าน: หมวดหมู่ สเปกที่จำเป็น รูปภาพ และ variant ที่พร้อมขาย
  7. กด Publish สินค้าจะเป็น ACTIVE และเปิดขายทันที
  8. หากไม่ขายแล้วให้ Archive แทนการลบประวัติ ส่วน Admin ยังระงับสินค้าที่ผิดนโยบายได้
S4ตอบคำถามสินค้าและดู Product Analytics

เส้นทาง: /th/seller/products/{productId}, /th/seller/analytics/products

  1. เปิดรายละเอียดสินค้าเพื่อดูคำถามจากผู้ซื้อ
  2. พิมพ์คำตอบและกดส่ง คำตอบจะปรากฏในหน้ารายละเอียดสินค้า
  3. เปิดเมนู Product Analytics เพื่อดูข้อมูลการมองเห็นและผลการทำงานของสินค้า
  4. ใช้ข้อมูลร่วมกับยอดขายและสต็อกในการปรับราคา เนื้อหา และโปรโมชัน
S5ปรับสต็อกและจุดสั่งซื้อซ้ำ

เส้นทาง: /th/seller/inventory

  1. ค้นหาสินค้าหรือ variant ที่ต้องการ
  2. ตรวจจำนวนคงเหลือ จำนวนที่ถูกจอง และจำนวนพร้อมขาย
  3. กรอก Quantity on hand และ Reorder level ด้วยจำนวนตั้งแต่ 0 ขึ้นไป
  4. กด บันทึก ระบบจะตรวจสิทธิ์ว่ารายการเป็นของร้านที่เลือก
  5. หากเกิด conflict ให้โหลดข้อมูลใหม่ก่อนแก้อีกครั้ง เพราะสต็อกอาจถูกจองจาก Checkout ระหว่างที่เปิดหน้า
S6แพ็ก ส่ง และปิดงานจัดส่ง

เส้นทาง: /th/seller/orders

  1. เปิดเมนู ออเดอร์ ค้นหาจากเลขออเดอร์ ชื่อลูกค้า หรือชื่อสินค้า และกรองสถานะ
  2. รายการ PENDING_PACK: ตรวจที่อยู่และสินค้า แล้วกด Pack
  3. รายการ PACKED: กรอกบริษัทขนส่งและเลขพัสดุ แล้วกด Ship
  4. รายการ SHIPPED: เมื่อตรวจว่าขนส่งส่งถึงแล้ว กด Deliver
  5. Buyer จะเห็นสถานะและเลขพัสดุในหน้าติดตามของตน
ขั้นตอนขนส่งเป็น Manual

ผู้ขายเป็นผู้กรอก tracking และกด Delivered เอง ระบบยังไม่ได้ดึงสถานะจาก carrier API อัตโนมัติ

S7อนุมัติหรือปฏิเสธคำขอคืนสินค้า

เส้นทาง: /th/seller/returns

  1. เปิดเมนู คืนสินค้า ค้นหาและกรองตามสถานะ
  2. ตรวจเลขออเดอร์ ผู้ซื้อ รายการสินค้า เหตุผล และหลักฐาน
  3. เมื่อสถานะเป็น REQUESTED กด Approve หากยอมรับ หรือ Reject หากไม่เข้าเงื่อนไข
  4. การคืนเงินจริงเป็นกระบวนการแยกและต้องให้ Admin ตรวจการชำระจากภายนอก
S8สร้างและจัดการคูปองร้าน

เส้นทาง: /th/seller/promotions

  1. กรอกโค้ด ชื่อคูปอง และเลือกส่วนลดแบบจำนวนเงินหรือเปอร์เซ็นต์
  2. กรอกมูลค่าส่วนลดแล้วกด สร้าง
  3. ค้นหาคูปองเดิมและกรอง Active/Inactive
  4. กด Disable/Enable เพื่อเปลี่ยนการใช้งาน หรือ Delete เพื่อลบคูปอง
  5. ผู้ซื้อใช้โค้ดบนหน้า Checkout ระบบจะตรวจสถานะและเงื่อนไขอีกครั้ง
S9ดูการเงินและขอ Payout

เส้นทาง: /th/seller/finance

  1. ตรวจยอดคงเหลือ ยอดรอเคลียร์ ยอดถอนได้ และรายการ ledger
  2. กรอกจำนวนเงินในส่วน Request payout โดยไม่เกินยอดถอนได้
  3. กดส่งคำขอ ยอดจะถูกสำรองและคำขอเป็น requested
  4. ติดตามประวัติ: approved, rejected หรือ paid
Payout เป็น Manual

สถานะ Paid หมายถึง Admin ยืนยันว่าดำเนินการโอนภายนอกแล้ว ระบบยังไม่มี Bank API

S10แชตและติดตามการแจ้งเตือน

เส้นทาง: /th/seller/chat, /th/seller/notifications

  1. เปิดเมนู แชต เลือกห้องจากชื่อผู้ซื้อ ร้าน สินค้า หรือออเดอร์ที่ผูกไว้
  2. อ่านประวัติ พิมพ์ข้อความ แล้วกดส่ง ระบบทำเครื่องหมายห้องว่าอ่านแล้ว
  3. เปิด การแจ้งเตือน เพื่อตรวจออเดอร์ชำระแล้ว Payout สำเร็จ/ถูกปฏิเสธ และเหตุการณ์ร้าน
  4. หากเปิด Web Push ไว้และ browser รองรับ สามารถอนุญาตการแจ้งเตือนจาก browser ได้

สถานะสำคัญของผู้ขาย

รายการ สถานะ การทำงานถัดไป
คำขอผู้ขาย DRAFT / SUBMITTED / APPROVED / REJECTED กรอกต่อ, รอตรวจ, เริ่มขาย หรือแก้แล้วส่งใหม่
สินค้า DRAFT / ACTIVE / SUSPENDED / ARCHIVED เตรียมข้อมูล, เปิดขาย, ถูกระงับ หรือหยุดขาย
Shipment PENDING_PACK → PACKED → SHIPPED → DELIVERED กดปุ่มตามลำดับเท่านั้น

Admin guide

คู่มือผู้ดูแลระบบ

ดูแลผู้ใช้ ร้าน สินค้า การเงิน เนื้อหา และความเสี่ยง

ต้องมี role ADMIN
Admin ไม่ใช่บัญชีซื้อขาย

บัญชี Admin ใช้ back office เท่านั้น ระบบบล็อก Cart และ Checkout สำหรับ role นี้ งานเปลี่ยนสถานะสำคัญควรตรวจหลักฐานและ audit log ทุกครั้ง

M1เข้าสู่ Admin Dashboard และอ่านงานค้าง

เส้นทาง: /th/admin หรือ /th/admin/dashboard

  1. เข้าสู่ระบบด้วยบัญชี role ADMIN หากไม่มีสิทธิ์ ระบบจะไม่แสดงหน้า Admin
  2. ตรวจการ์ด KPI และ exception เช่นร้านรออนุมัติ สินค้ารอตรวจ คืนสินค้า และ Payout
  3. เปิดงานจากเมนู sidebar ตามประเภท ไม่ควรตัดสินจากยอดรวมบน Dashboard เพียงอย่างเดียว
  4. ใช้เมนูบัญชีด้านล่างเพื่อดู Profile, Billing/Payouts, Settings หรือออกจากระบบ
M2ตรวจ KYC และอนุมัติคำขอผู้ขาย

เส้นทาง: /th/admin/shops

  1. เปิดเมนู ร้านค้า แล้วดูส่วน Seller Applications
  2. ขยายคำขอเพื่อตรวจข้อมูลผู้สมัคร ร้าน ประเภทธุรกิจ บัญชีรับเงิน ที่อยู่รับสินค้า และเอกสาร
  3. ตรวจเอกสารทีละรายการ แล้วกด Approve document หรือ Reject document พร้อมเหตุผล
  4. เมื่อเอกสารบังคับทุกชิ้นถูกตัดสินแล้ว กด Approve application เพื่อสร้าง/เปิดร้านและปลดล็อก Seller
  5. หากข้อมูลไม่ผ่าน กด Reject application กรอกเหตุผลที่ผู้สมัครแก้ไขได้ แล้วส่งกลับ
ระบบป้องกันการอนุมัติเร็วเกินไป

หากเอกสารบังคับยังมีสถานะ Pending ปุ่มอนุมัติคำขอจะไม่ผ่าน และระบบจะแสดงประเภทเอกสารที่ยังไม่ตัดสิน

M3จัดการร้านค้า

เส้นทาง: /th/admin/shops

  1. ค้นหาร้านจากชื่อ slug หรือเจ้าของ และกรองตามสถานะ
  2. ใช้ Edit เพื่อแก้ข้อมูลที่ Admin ดูแลได้
  3. ใช้ Update status เพื่อเปลี่ยนเป็น Active, Suspended, Rejected, Banned หรือ Vacation ตามเหตุผล
  4. ใช้ Delete เฉพาะกรณีที่ตรวจผลกระทบกับสินค้า ออเดอร์ และข้อมูลการเงินแล้ว
M4ตรวจนโยบายและระงับสินค้า

เส้นทาง: /th/admin/products, /th/admin/products/{productId}

  1. เปิดเมนู สินค้า เพื่อค้นหาสินค้าที่เปิดขาย หรือถูกระงับ
  2. เปิด Detail เพื่อตรวจชื่อ รายละเอียด รูป หมวดหมู่ ราคา variant สต็อก สเปก และ readiness
  3. หากสินค้าที่เปิดอยู่ฝ่าฝืนนโยบาย กด Suspend พร้อมเหตุผล; เมื่อแก้แล้วใช้ Restore
M5จัดการผู้ใช้และสิทธิ์

เส้นทาง: /th/admin/users

  1. ค้นหาและกรองผู้ใช้ตาม role หรือสถานะ
  2. กดสร้างผู้ใช้ใหม่ กรอกชื่อ อีเมล รหัสผ่าน และเลือก USER หรือ ADMIN
  3. กด Edit เพื่อแก้ชื่อ อีเมล หรือ role
  4. กด Delete แล้วตรวจอีเมลในกล่องยืนยันก่อนลบ ระบบไม่ให้ลบบัญชี Admin ที่กำลังใช้งานเอง
  5. การเป็น Seller ต้องมาจากร้าน Active ห้ามเปลี่ยน role เป็น Seller เพราะไม่มี role ดังกล่าว
M6ติดตามออเดอร์และ Payment

เส้นทาง: /th/admin/orders

  1. ค้นหาจากเลขออเดอร์หรือข้อมูลสินค้า และกรองตามสถานะออเดอร์หรือร้าน
  2. ตรวจสถานะออเดอร์ สถานะชำระ ยอดรวม จำนวนสินค้า shipment และ refund
  3. ใช้หน้านี้สำหรับ monitoring ปัจจุบันไม่มีปุ่มให้ Admin บังคับ Payment สำเร็จ
  4. หากพบ Payment ค้าง ให้ตรวจ provider/webhook และ audit ก่อนดำเนินการด้าน Refund หรือ Fulfillment
M7จัดการ Return และ Refund

เส้นทาง: /th/admin/returns, /th/admin/refunds

  1. ที่หน้า Returns ค้นหาคำขอ ตรวจผู้ซื้อ ออเดอร์ รายการ เหตุผล และสถานะ
  2. ใช้ Update status เพื่อสะท้อนผลการตรวจ เช่น Approved, Rejected, Received หรือ Completed
  3. ที่หน้า Refunds ตรวจเลขออเดอร์ provider จำนวนเงิน และสถานะ
  4. เปลี่ยน Refund เป็น Processing ก่อน และเปลี่ยนเป็น Success เฉพาะหลังผู้ให้บริการยืนยันว่าเงินคืนสำเร็จ
  5. หากผู้ให้บริการปฏิเสธหรือผิดพลาด ให้เปลี่ยนเป็น Failed และบันทึกหลักฐานภายนอกตาม runbook
Refund เป็น Manual

ปุ่มใน Admin เปลี่ยนสถานะฐานข้อมูล ไม่ได้เรียก Payment Provider เพื่อคืนเงินโดยอัตโนมัติ

M8อนุมัติ ปฏิเสธ และยืนยัน Payout

เส้นทาง: /th/admin/payouts

  1. กรองรายการตาม requested, approved, rejected, paid หรือ cancelled
  2. ตรวจร้าน จำนวนเงิน สกุลเงิน ยอดใน wallet และคำขอซ้ำ
  3. รายการ requested: กด Approve เมื่อตรวจผ่าน หรือ Reject เมื่อต้องคืนยอดที่สำรอง
  4. หลังดำเนินการโอนเงินนอกระบบและตรวจผลแล้ว รายการ approved จึงกด Paid
  5. ตรวจ Audit Logs เพื่อยืนยันผู้อนุมัติและผู้กดจ่าย
ควรใช้การอนุมัติสองคน

ระบบยังไม่บังคับ Bank API หรือ two-person approval ใน UI ผู้ปฏิบัติงานต้องทำตามกระบวนการองค์กร

M9Moderate รีวิว รายงาน คำถาม และคำตอบ

เส้นทาง: /th/admin/content-moderation

  1. เลือกคิว Reviews, Reports, Questions หรือ Answers
  2. กรองสถานะและตรวจเนื้อหา เจ้าของ รายการที่เกี่ยวข้อง และเหตุผลการรายงาน
  3. เลือกสถานะใหม่จากปุ่ม Action
  4. เมื่อตั้ง Review เป็น Rejected/Hidden, Report เป็น Resolved dismissed หรือ Question/Answer เป็น Hidden ให้กรอก note ก่อนยืนยัน
  5. แจ้งเหตุผลที่กระชับและอ้างอิงนโยบาย เพื่อให้ Audit ตรวจย้อนหลังได้
M10จัดการ Catalog, หมวดหมู่, แบรนด์ และสเปก

เส้นทาง: /th/admin/catalog, /th/admin/categories

  1. หน้า Catalog ใช้ดูรายการสินค้าและแก้รายละเอียดรายการที่เลือก
  2. ส่วน Brands ใช้สร้าง แก้ไข เปิด หรือปิดแบรนด์
  3. หน้า Categories ใช้สร้าง/แก้หมวดหมู่ กำหนด slug ลำดับ และสถานะ Active
  4. เลือกหมวดหมู่แล้วเพิ่ม Category Specs ระบุชื่อ ชนิดข้อมูล ตัวเลือก และบังคับกรอกหรือไม่
  5. ปิดหมวดหมู่/สเปกด้วย Deactivate แทนการลบ หากมีสินค้าผูกอยู่
M11ดูแล Affiliate, Fraud และ Audit Logs

เส้นทาง: /th/admin/affiliates, /th/admin/fraud, /th/admin/audit-logs

  1. Affiliate: ค้นหาผู้สร้างลิงก์ ตรวจโค้ด/สถิติ และเปลี่ยนสถานะ Active หรือ Disabled
  2. Fraud: กรองตามสถานะและระดับความเสี่ยง ตรวจ risk score และเหตุผล
  3. กด Review เพื่อรับเคส จากนั้นเลือก Resolve เมื่อจัดการแล้ว หรือ Dismiss เมื่อไม่ใช่ความเสี่ยงจริง
  4. Audit Logs: ค้นและกรองเหตุการณ์เพื่อดู actor, action, entity และเวลาที่เกิด
  5. ใช้ Audit Logs ตรวจการเปลี่ยน Seller application, Product, Refund และ Payout โดยเฉพาะ
M12อ่าน Reports, Profile และ Settings

เส้นทาง: /th/admin/reports, /th/admin/profile, /th/admin/settings

  1. Reports แสดงยอดขายที่ชำระแล้ว มูลค่าออเดอร์เฉลี่ย Refund exposure Payout Commission และจำนวนสินค้า
  2. Profile แสดงชื่อ อีเมล role รหัสผู้ใช้ และข้อมูล session แบบอ่านอย่างเดียว
  3. Settings อ่านและแก้ไขค่ากำหนดที่ไม่ใช่ข้อมูลลับผ่าน SystemSetting API ส่วน credential ยังจัดการผ่าน deployment secrets
  4. ใช้เมนูเปลี่ยนธีมบน sidebar หากต้องการสลับรูปแบบการแสดงผล Admin
สิ่งที่ยังไม่มีใน UI

Reports ยังไม่มีปุ่ม export/date range และอัตรา commission ยังจัดการผ่าน deployment configuration โดยหน้า /admin/commissions ใช้ตรวจสอบ อนุมัติ หรือยกเลิกรายการจริงพร้อมบันทึกเหตุผล

แก้ปัญหาเบื้องต้น

ตรวจตามลำดับก่อนแจ้งผู้ดูแลระบบ

01เข้า Checkout ไม่ได้หรือปุ่มถูกปิด
  • ตรวจว่าเข้าสู่ระบบและยืนยันอีเมลแล้ว
  • เลือกรายการในรถเข็นอย่างน้อยหนึ่งรายการ
  • เพิ่มที่อยู่และเลือกที่อยู่สำหรับจัดส่ง
  • ตรวจว่าสินค้า ร้าน และ variant ยัง Active และมีสต็อก
02Payment ค้าง Pending
  • อย่ากดเปลี่ยนสถานะจาก browser
  • รีเฟรชหน้า Return หรือเปิดรายละเอียดออเดอร์
  • Local: ตรวจว่ากด event บน Mock Payment แล้ว
  • Production: ให้ผู้ดูแลตรวจ webhook signature, provider reference และ audit log
03เมนู Seller ใช้งานไม่ได้
  • ตรวจว่าล็อกอินด้วยบัญชีผู้สมัคร
  • เปิด /th/seller/status ดูสถานะล่าสุด
  • SUBMITTED ต้องรอ Admin; REJECTED ต้องแก้และส่งใหม่
  • ต้องมีร้าน ACTIVE อย่างน้อยหนึ่งร้าน
04ส่งสินค้าเข้าตรวจไม่ได้
  • ตรวจ Readiness ทุกข้อ
  • เลือกหมวดหมู่และกรอกสเปกบังคับ
  • มีรูปอย่างน้อยหนึ่งรูปและกำหนดรูปหลัก
  • มี variant Active ราคาเกิน 0, SKU ไม่ซ้ำ และชุดตัวเลือกไม่ซ้ำ
05ปุ่ม Pack, Ship หรือ Deliver ถูกปิด
  • ปุ่มทำงานตามลำดับสถานะเท่านั้น: Pending pack → Packed → Shipped → Delivered
  • Ship ต้องกรอกบริษัทขนส่งและเลขพัสดุ
  • ตรวจว่าเลือกหน้าร้านถูกต้องเมื่อบัญชีมีหลายร้าน
06Admin อนุมัติ Seller ไม่ผ่าน
  • เปิดเอกสารทุกชิ้นและตัดสิน Approve/Reject
  • ตรวจรายการ unresolved required documents
  • หากเอกสารถูก Reject ให้ปฏิเสธคำขอพร้อมเหตุผลเพื่อให้ผู้สมัครอัปโหลดใหม่
07Upload หรือ Push Notification ใช้ไม่ได้
  • Upload: ตรวจชนิดไฟล์ ขนาดไฟล์ และการตั้งค่า Local/S3 storage
  • Push: ตรวจว่าเปิด Push ในระบบ browser อนุญาต และเว็บไซต์ใช้ HTTPS; iOS ต้องติดตั้ง PWA ก่อน
  • หาก Push ใช้ไม่ได้ การแจ้งเตือนในหน้าระบบยังเป็นแหล่งข้อมูลหลัก
