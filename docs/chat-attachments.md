# Chat images and files

The buyer and current active shop owner send one message with up to five files and an optional caption. Defaults allow JPEG, PNG, WebP, PDF, UTF-8 TXT/CSV, DOCX, XLSX, PPTX and ZIP. Each file may contain 10 MiB and the files together may contain 20 MiB. The multipart request cap is 21 MiB. These limits are implementation policy; the quotation does not specify limits.

`POST /api/chats/:roomId/messages` retains JSON text requests. Multipart requests repeat the `files` field and require `clientMessageId`, a UUID. Optional fields are `body`, `productId`, `orderId` and `scope`. Unknown fields and duplicate scalar fields fail. The API reads at most 21 MiB before parsing multipart, including requests without Content-Length, and cancels reads after 30 seconds. Unrelated JSON ingress keeps its existing limit.

`ChatAttachment` rows belong to messages and carry ordered verified metadata and SHA-256. The repository compares filename, type, size, kind, digest and order together with sender, room, caption and context under the thread lock. Identical UUID retries return the original message and attachment IDs. Conflicting UUID reuse returns 409. New messages alone publish realtime and notifications. Legacy attachment strings remain inert.

Private immutable objects are written before the message transaction. Local storage exclusively publishes objects outside public storage. S3 uses conditional PutObject with `If-None-Match: *` and a SHA-256 checksum. Configure the bucket to deny anonymous reads, block public access and deny public ACLs. A key prefix alone does not make S3 private. S3-compatible providers must support conditional create and checksum validation; unsupported providers fail the send. Generic presigned and public upload methods refuse chat keys.

`GET /api/chats/:roomId/attachments/:attachmentId/content` checks the current participant and live message relation on every read and streams private bytes. Optional `scope` and `shopId` further restrict access. `mode=download` downloads images; default or `mode=preview` displays verified rasters. Documents always download. Responses use the verified MIME, UTF-8 filename, safe ASCII fallback, private/no-store and nosniff. ADMIN and shop staff cannot read participant attachments. Disabling chat blocks sends while retaining history and downloads.

Image validation decodes bounded raster pixels with Sharp. Text validation uses fatal UTF-8 decoding and rejects binary controls. PDF validation checks bounded header and EOF signatures. ZIP validation checks the bounded central directory, local entry agreement, paths, encryption, compression method and declared expansion limits without decompressing content. Office files require their matching package part and reject macro parts. These checks do not scan documents for malware or prove semantic validity. Documents never render inline.

Storage failures before message persistence and confirmed successful replays check database references before removing request-owned objects, deferring cleanup on database errors. Any message persistence exception retains all written objects for grace-period reconciliation because an in-flight commit may still become visible. A crash may leave private orphan objects. `bun run scripts/reconcile-chat-attachments.ts [cursor]` examines at most 100 objects per page and removes only unreferenced objects older than 48 hours. Run successive pages using the returned cursor. Database outage fails the maintenance operation before deletion. This command is an explicit maintenance action; do not run it against customer storage without operational authorization. Back up attachment storage together with PostgreSQL and retain committed objects as long as their rows exist.

Local reconciliation scans directory names to select a sorted page with bounded memory. Its scan time grows with directory entries. S3 uses provider pagination. Temporary local objects left by a crash are included after the same grace period.

Nginx admits at most 21 MiB only on the exact UUID message path. Application middleware permits that size only for multipart POST, and the route enforces actual bytes. Bun has the corresponding transport ceiling. Browser traffic uses the same-origin Next rewrite. Next's proxy buffer ceiling is 21 MiB to prevent its default 10 MiB clone limit from truncating valid multipart bodies. Application limits remain authoritative.

The shared buyer/seller composer snapshots the original UUID, ordered File objects, caption and context for retry. Selection and draft changes increment revision. An old send can clear a draft only when its revision still matches. Preview object URLs are revoked on removal and unmount.

Native HTTP parser regression runs with `bun run scripts/chat-native-http-regression.mjs` and through the Vitest chat suite. It starts an ephemeral Bun listener with the real chat routes, observability and security plugins, asynchronous authentication and send-service test doubles, then stops the listener in `finally`. It checks JSON, an actual PNG above 1 MiB, repeated files with Thai names, UTF-8 text, six-file and duplicate-field rejection, chunked multipart, malformed bodies, and fixed/chunked size rejection. Service, storage and database behavior remain covered by their separate tests.

On Windows Bun 1.3.14, the original parser successfully drained the native body but `reader.releaseLock()` then threw `TypeError: undefined is not a function`. Instrumentation confirmed the method existed and all 37 JSON bytes had been read; a generic standalone reader did not reproduce the exception. Restoring that call makes the native HTTP regression fail on its first valid JSON request. The parser now clears its deadline timer without releasing its exclusively owned drained/canceled reader. Byte caps and cancellation are unchanged. Elysia wraps parser errors in `ParseError.cause`; composition configures both global formatters to defer only known chat parser errors to the scoped chat handler, preserving their status and code. Infrastructure accepts generic callbacks and does not import the Chat domain.

Multipart parsers may append MIME parameters such as `charset=utf-8`. Agreement checks compare the supplied MIME essence with the allowed extension. The stored MIME stays canonical, and strict byte validation still decides whether the file is accepted.

Multipart also accepts `replyToMessageId` and `replyToAttachmentId`. Selected-image deletion revokes content access while retaining private bytes and immutable metadata. See [chat message actions](chat-actions.md) for reply, deletion, and refresh behavior.
