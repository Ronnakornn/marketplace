Problem

Two modules emit two shapes for the same Product, so the browser pays for reconciliation: 350 lines of hand-rolled toRecord/readString/readNumber sitting on top of a type-safe Eden client that already knew the types.

Solution

Agree one buyer-facing Product shape on the server; catalog and search both emit it. The normalizer's interface shrinks to a typed mapper — or disappears.

Deletion test

Delete the normalizer today and the coercion reappears at every call site — it earns its keep. Delete it after the shapes agree and nothing reappears. That gap is the opportunity.

Wins

  • · Leverage: Eden types reach the components
  • · Locality: one Product shape, one place
  • · Stock formula stops appearing 4×
  • · Kills the data ?? items sniffing (4 sites)
  • · Interface shrinks; ~350 lines absorbed
  • · Tests stop needing a second normalizer
Evidence — ProductBuyerStates.test.tsx:171-190 mocks #/features/product/queries wholesale and reimplements the normalizers inside the test. 1,473 lines of tests, and not one exercises the real reconciliation. The duplication is structurally invisible to the suite.

Payment, shipment, and the expiry job all call the same interface. The status pair (status + paymentStatus) moves together, by construction.

Problem

The transition core is already provider-agnostic, but seven sites across two modules hardcode 'mock' — including the checkout module building a mock URL path. Payment.provider stores a buyer-chosen string ("card", "cod"), so it isn't a provider identity at all.

Solution

One port: create intent, produce redirect URL, verify signature, map provider events to the internal payment.paid|failed|expired vocabulary.

Why only "worth exploring"

One adapter means a hypothetical seam. Do this when the second provider is actually being added — not before. The evidence for doing it soon: 'cod' is already a second path that silently falls out of the flow.

Wins

  • · Checkout stops knowing about mock
  • · Two adapters make the seam real
  • · Per-provider webhook secrets
  • · 'cod' gets a home
  • · Core stays untouched when adding a provider
